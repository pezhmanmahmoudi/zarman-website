Customer archive error investigation and validation — 2026-10-09 (Australia/Sydney)

Observed screenshots
- Hydration attribute mismatch on the pagination input: data-rtl-listener="true".
- Runtime InvalidStateError from AdminToast.useEffect calling showPopover() on a disconnected element.

Confirmed code cause
KycActionButtons publishes the action result and updates the visible queue before the confirmation lifecycle finishes. Removing the queue row also removes its confirmation dialog. The previous global toast could still portal into that dialog using the dialog stack snapshot, then call showPopover() from a passive effect after the host had detached. The browser rejects showing disconnected popovers. This is a notification-rendering error; the screenshot alone does not establish whether the database archive succeeded or failed.
The previous AdminToast implementation from git HEAD was exercised with an intentionally detached node; its effect reproduced InvalidStateError: Invalid on disconnected popover elements. This is an offline lifecycle simulation, not a live browser reproduction.

Changes
- AdminToast is an ordinary fixed React notification, hosted within a connected open admin dialog or document.body. It no longer calls showPopover/hidePopover or uses a popover attribute.
- Hydration uses matching server/initial-client snapshots before rendering a portal; live-region roles and dismissal remain accessible.
- The dialog stack skips disconnected and closed hosts, including nested dialogs. Native dialog setup/cleanup runs in a layout effect and never opens a detached node. Keyboard handling checks for a missing dialog.
- Confirmation guards block double submits and premature cancellation; completed/cancelled callbacks are cleared so stale clicks cannot replay a write.
- archiveKyc verifies authorization, checks read errors and profile existence, matches the displayed status when supplied, and conditionally updates the previous status. It confirms the returned row before claiming success. Already-archived profiles return success without another write/audit.
- An audit logging failure after a committed archive is logged and returned as a warning, rather than silently discarded or presented as a failed archive. The existing audit insert remains separate from the profile update; this change does not claim a database transaction across both operations.
- Both queue and profile display the committed status even if their follow-up read fails. The profile editor's status is updated with the commit so a later identity edit cannot restore its old status.
- Pagination now has a numeric input with min/max/step and explicit LTR direction. Output is deterministic with browser globals present; hydration warnings are not suppressed.

Hydration warning limits
No data-rtl-listener writer was found in tracked project code or app/components/lib/public/scripts. An extension or externally injected RTL helper is a likely source, but the responsible browser script has not been identified. A fresh browser profile without extensions can distinguish that case. A numeric input may avoid text-input RTL helpers, but the app cannot guarantee that third-party DOM injection stops. No blanket suppressHydrationWarning was introduced.
