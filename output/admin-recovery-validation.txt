Admin mutation recovery — local implementation, 2026-10-08

Verified defect
Admin authorization and cached admin reads used a Supabase client that could write renewed auth cookies during a Server Component render. The fault-injection test reproduces the old cookie-write exception and verifies the read-only path. This demonstrates a code defect; no production digest or server log was provided, so it does not establish the cause of every live occurrence.

Implemented behavior
- Read-only session client for render-time admin authorization; existing access and capability checks remain.
- Scoped data refreshes for transactions, KYC, customers, treasury, ledger entries, feedback, reports and platform settings.
- Retain last successful data, display a local retry notice, and preserve mounted forms on subsequent read failures.
- Apply confirmed transaction deletion and KYC decisions locally; prevent older reads from undoing them.
- Catch rejected admin transitions before the route error boundary. Never automatically replay a write after an interrupted response.
- Receipt cleanup transport failure returns a warning after a committed database deletion.
- Keep the full route recovery screen for initial/render failures and add a support reference.
